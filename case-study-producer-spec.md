# Case Study Producer — Detailed Spec (Honours Boards)

This is the first module being built. It converts completed install jobs into published case studies on `honours-boards.co.uk` plus social variants for Facebook, Instagram, and Pinterest. Always with human review.

## End-to-End Workflow

1. Honours boards job is installed.
2. Team drops files into a Drive folder (see structure below).
3. Operator opens the dashboard, sees the folder in the **Pending** queue.
4. Operator clicks **Generate**. System:
   - Reads the sales order PDF and proof PDF.
   - Vision-analyses the photos.
   - Drafts all CMS text fields, picks 2 hero photos, resizes them.
5. Operator reviews the draft in the dashboard — edits text inline, swaps photos, regenerates sections, sets Club Type.
6. Operator clicks **Approve**. System pushes the case study to the Wix CMS as a draft item (not yet published).
7. Operator does a final pass in Wix and publishes from there.
8. After Wix publish, social variants for FB, IG, Pinterest are queued for separate approval.
9. Approved social posts are scheduled or published immediately.

## Image Requirements

- **Two images per case study**, both **1200 × 900 px (4:3)**.
- **Main Image** — hero shot. Ideally the finished board installed on its wall, well-lit, framed cleanly.
- **Image 2** — detail shot. Close-up of lettering, frame, crest, or unique design feature.
- Sharp library handles resize/crop. Use `sharp(input).resize(1200, 900, { fit: 'cover', position: 'attention' })` as the default; allow operator override.
- Alt text generated by vision pass — reference the customer, the board type, and the visible features. Length 80–140 chars.

Example alt texts from existing case studies:

- "Wooden cricket honours board for The Hit or Miss Cricket Club showing yearly batting and bowling records."
- "Large dark wood Masonic honours board for St Aubyn Chapter No 20 installed on an interior wall"
- "Oxford University Lawn Tennis Club honours board with blue ACM panel and oak frame."

## Voice Guidelines

Distilled from the existing case studies at https://www.honours-boards.co.uk/honours-board-examples (read 3–5 of them before drafting).

**Tone:** friendly, informative, expert, British, slightly understated, soft-sell. Never pushy. Never generic. Confident from experience.

**Total length target:** ~500–800 words across the three text sections combined.

**Structural pattern (consistent across all existing case studies):**

- **Introduction Text** opens with the customer or the problem, not with us. Establishes what they needed.
- **Design Highlights** is the technical / craft section. Specifics in bold. Material, dimensions, finish, lettering, fixings, layout choices. May include an internal link to a relevant category page.
- **Summary** zooms out — the wider point about this type of project, our experience with similar work, and a soft pitch to the reader.
- **CTA** is one or two sentences inviting contact.

**Recurring opening patterns to draw from (not copy):**

- "When a [type of] club commissions a new honours board, it is rarely just about adding names to a wall."
- "[Customer] required a bespoke honours board to record..."
- "[Customer] wanted to refresh and rebrand their clubhouse..."
- "Not every cricket honours board needs to follow the usual format..."

**Recurring phrasings:**

- "We designed and manufactured..."
- "We worked closely with the club..."
- "This board was produced from..."
- "For [type of] clubs in particular..."
- "If you're planning..." / "If you are looking for..."
- "get in touch"

**Things to avoid:**

- Hype words: "stunning", "incredible", "amazing"
- Generic AI tells: "In the world of...", "When it comes to...", "Look no further than..."
- Padding: every sentence should add a specific detail
- Repeating the customer name more than 3 times across the body
- Mentioning price unless the existing case study pattern does (most do not)
- Claims about timescales, warranty, or process that aren't backed by the source materials

## Wix HTML Formatting Rules

The body fields contain HTML formatted to match Wix Studio's editor output. Generate exactly this:

**Paragraphs:**
```html
<p class="font_8">Paragraph text here.</p>
```

**Blank line / spacer between paragraphs:**
```html
<p class="font_8"><br></p>
```

**Bold (for specifications inline):**
```html
<p class="font_8">The board was made at <strong>1200 × 600mm</strong> with a <strong>solid oak frame</strong>.</p>
```

**Internal links (always bold and underlined):**
```html
<a href="https://www.honours-boards.co.uk/wooden-honours-boards"><u><strong>wooden honours boards</strong></u></a>
```

**Unordered list:**
```html
<ul class="font_8">
  <li><p class="font_8">First item</p></li>
  <li><p class="font_8">Second item</p></li>
</ul>
```

**Internal links to standard pages:**

- `/wooden-honours-boards`
- `/acrylic-honours-boards`
- `/honours-board-lettering`
- `/honours-board-examples`
- `/wooden-honours-boards/wood-types`
- `/honours-boards/cricket-honours-boards` (and other sport-specific pages — check existence before linking)

Aim for 1–3 internal links across the whole case study, no more.

## Supabase Schema (Initial Sketch)

```sql
-- Brands (multi-brand from day one)
create table brands (
  id uuid primary key default gen_random_uuid(),
  slug text unique not null,        -- 'honours-boards', 'signet-signs', 'signet-play'
  name text not null,
  website_url text not null,
  wix_site_id text                  -- for API calls
);

-- Club Type vocabulary
create table club_types (
  id serial primary key,
  name text unique not null,
  brand_id uuid references brands(id)
);

-- Main case study record
create table case_studies (
  id uuid primary key default gen_random_uuid(),
  brand_id uuid references brands(id) not null,
  status text not null default 'pending', -- pending | draft | approved | published | failed
  drive_folder_id text not null,
  drive_folder_name text not null,        -- e.g. '(60111) Thorpe Willoughby Sports Association'
  so_number text,
  customer_name text,

  -- Extracted spec
  board_type text,        -- Wooden | Acrylic | Lettering
  board_size text,
  back_colour text,
  text_colour text,
  edge_details text,
  fixings text,

  -- Generated content (HTML)
  h1_page_title text,
  h1_introduction_text text,
  h2_design_highlights_title text,
  h2_design_highlights_text text,
  h2_summary_title text,
  h2_summary_text text,
  cta_text text,
  page_meta_title text,
  page_meta_description text,
  schema_title text,
  schema_desc text,

  -- Categorisation
  club_types text[],   -- ['Cricket'], ['Masons']

  -- Wix linkage
  wix_item_id text,
  wix_url_slug text,

  -- Audit
  created_at timestamptz default now(),
  updated_at timestamptz default now(),
  generated_at timestamptz,
  approved_at timestamptz,
  published_at timestamptz
);

-- Photos selected and processed for a case study
create table case_study_photos (
  id uuid primary key default gen_random_uuid(),
  case_study_id uuid references case_studies(id) on delete cascade,
  drive_file_id text not null,
  original_filename text,
  role text not null,              -- 'main' | 'image_2' | 'candidate'
  alt_text text,
  processed_storage_path text,     -- path in Supabase Storage for the 1200x900 version
  wix_media_url text,              -- after upload
  selected boolean default false,
  created_at timestamptz default now()
);

-- Social variants for a case study
create table social_posts (
  id uuid primary key default gen_random_uuid(),
  case_study_id uuid references case_studies(id) on delete cascade,
  brand_id uuid references brands(id) not null,
  platform text not null,           -- 'facebook' | 'instagram' | 'pinterest'
  status text not null default 'draft',  -- draft | approved | scheduled | published | failed
  body text,
  image_url text,
  scheduled_for timestamptz,
  published_at timestamptz,
  external_post_id text,
  created_at timestamptz default now()
);
```

## Build Order

Strictly sequential. Each step ends with something working and testable.

1. **Supabase setup** — create project, run initial migrations, seed `brands` and `club_types`.
2. **Next.js scaffold** — App Router, Tailwind, Supabase client (server + browser).
3. **Google Drive integration** — service account auth, list folders in `1-Pending`, fetch file metadata.
4. **Dashboard skeleton** — top-level routes, navigation, "Case Studies" section.
5. **Pending queue page** — show all folders in `1-Pending` with status, file list per folder.
6. **PDF extractor** — read sales order and proof PDFs, extract structured spec data. Test against the Thorpe Willoughby files.
7. **AI text generator** — voice-grounded prompt, generate all 11 text fields. Test output against existing case studies for quality.
8. **Photo handling** — fetch photos from Drive, vision pass to suggest 2 best shots, resize to 1200×900, store in Supabase Storage.
9. **Review UI** — case study detail page with inline editing, photo picker, regenerate-this-section buttons, Club Type picker.
10. **Wix push** — upload images to Wix Media, create CMS item via Wix Data API (or MCP connector), set as draft.
11. **Drive housekeeping** — on successful publish, move folder from `1-Pending` to `3-Published`.
12. **Social variant generator (Phase 2)** — generate FB / IG / Pinterest copy from approved case study.
13. **Social approval and scheduling (Phase 2)** — queue, approve, schedule, publish.
